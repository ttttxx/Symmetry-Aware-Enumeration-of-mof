# 当前算法、main_MATCH.tex 差异及重测建议（2026-11-16）

本轮只分析论文修改点，未修改论文正文、表格或已发布数据包。重测使用 ABI 3、C++ DFS、紧凑完整代表 Trie，并显式开启搜索前缀覆盖缓存。原六例全部保留，增加原论文三个小/中算例；vba 单列与论文匹配输出总数的受限测试。

论证主线：子群固定点任务保留；利用已完成区域减少交叠搜索，沿 DFS 复用群比较状态，在叶节点直接取得规范性与稳定子，再由紧凑 Trie 保存唯一代表。性能结论依赖同群、同输出和实际运行规模。

## 一、方法与实现的区别

| 位置 / 问题 | 当前论文 | 当前优化后端 | 建议怎么改 |
|---|---|---|---|
| 2.1 指派空间、群作用、规范代表、ρ | 固定嵌入网络、相容节点指派、Γ 轨道 | 数学对象保持一致 | 保留定义和公式，不扩大等价范围 |
| 2.2 子群格与固定点任务 | 合并相同顶点划分，允许 Fix(H) 交叠 | 保留子群组织，额外记录已经完整搜索的任务域，将等色条件编译进后续 DFS | 在任务组织后补一段跨任务排除；明确只有已完成任务能登记整域覆盖，子群域自身仍相交 |
| 2.2 规范前缀比较 | 每层从固定顶点顺序比较；active 保存未决操作 | 额外保存每个操作已经确认相等的位置；后代从游标继续，出现确定差异即可短路 | 保留剪枝判据，补充比较游标与回溯恢复，不把这一点称为新规范性定义 |
| Algorithm 1 叶节点 | 再求 κ(c)，再求完整稳定子 | 完整叶已经是字典序最小元；稳定子阶数为 1 + 存活非恒等操作数 | 普通优化 DFS 中删去重复全群扫描，改为直接接受叶子与读取稳定子；补不变量说明 |
| 全局成员检查 | 抽象 seen-canonical cache | 路径压缩的完整键数组 Trie；结果键被边引用，取消 C++ 哈希与 Python 哈希副本 | 正文交代精确查重，数组布局、节点字段与内存界放附录/实现说明 |
| 搜索前缀 Trie | 未描述 | 另一个可选覆盖缓存，保存中断任务已完成的兄弟子树；查询还需来源任务等色约束和允许标签域包含关系 | 与完整代表 Trie 分开命名和说明。开放路径不能标记为完成；容量满可少存证书，不影响正确性。当前证据不足以作为普遍加速主因 |
| 完备性段落 | 由恒等任务、前缀剪枝、叶规范化及成员检查论证 | 再增加已完成区域的安全排除 | 将“叶规范化映射到最小元”改为“存活叶已规范”；证明新增覆盖排除仅移除已处理的规范搜索区域。仍要求穷尽且无截断 |
| Python / C++ 实现 | 未交代新混合边界 | Python 组织任务，C++ 一次执行整个任务 DFS，批量导出，Python 解码/排序 | 补实现段和运行配置；同时报告总 enumerate 时间与 C++ 核时间；不能把 C++ 收益全算作搜索理论收益 |
| 精确 ρ 配额分支与附录证明 | 同一 Algorithm 1 覆盖普通/配额调度 | 新后端只覆盖普通调度；旧 RhoQuotaMOFEnumerator 继续承担论文配额实验 | 明确两条执行路径。优先正文写普通优化 DFS，配额保留独立算法/附录说明；精确层完成不能当成整个 Fix(H) 完成 |
| 默认入口 | 读者可能以为默认即论文算法 | CLI 默认仍 legacy，新后端需显式 cpp / trie；前缀缓存默认关闭 | 方法/复现说明明确论文采用的配置；是否改默认需另行决定 |

## 二、结果部分与表 2 怎么改

1. `main_MATCH.tex:475–477` 的 CASM 对照段需要重写。原稿比较 Γ 与原生 F，侧重群选择对计数的影响；新性能主表比较相同 Γ、相同节点池、相同结果字段。原生 F 的轨道计数仍可保留在附表，承担等价群差异的说明。
2. 表 2 建议列：拓扑、C3/C4、原始指派数 |X|、轨道数 |X/Γ|、本文时间、CASM(Γ)时间、速度比。CASM(F)计数与百分差不再和同群性能挤在同一主表。原稿五个算例保留，增加 ffc 与 fjh 的规模梯度；lil 可留补充材料，并明确为新增拓扑。
3. 时间应称“枚举总耗时”：包含本文子群准备、搜索、结果保存、标签解码和排序；双方图/群构建、依赖导入、正确性验证在计时外。它既不等于单独的 C++ 核耗时，也不包含 CIF 重构/GCMC/DFT。
4. 注明 CASM 2.3.1、相同 Python 3.11.1、三次独立进程中位数、单线程环境变量及未固定 CPU affinity。主比较是指定 Γ 的 CASM 底层接口与配套结果构建流程；另给同群只计数时间，说明输出工作量的影响。这些结果不能代表 CASM 所有模块的最佳可能性能。
5. 补充 Burnside 独立轨道计数、实际位点置换集合一致、轨道大小整数和等于 |X|、归一完整记录摘要一致。CASM 取最大代表，本文取最小代表，在计时外统一规范约定再比较。
6. 结论按规模限定：小例有固定准备成本，不能声称全部算例更快；相对速度与 |X| 不必单调，还受群作用、可变位点和输出轨道数影响。附表保留峰值 RSS 与重复测量范围。
7. 论文 `vba` 表用于回答输出分层问题。当前优化普通 DFS 可在相同输出总数下重测速度与组成；新后端未接入精确层配额，不替换原表配额列/层时间，也不能用普通输出总数证明各层覆盖。
8. 摘要与贡献项保留作者已确定的 subgroup lattice；如增加效率表述，放入实测范围与比较条件。结论同步分开写“同 Γ 下效率”和“Γ/F 下计数差异”。数据可用性部分以后需增加新脚本、配置和原始结果，并重新导出导师用无注释包。

## 三、优化口径

- **少搜重复区域**：以前不同子群任务常搜到同一批指派；现在把已完成域的约束带到后续任务，能证明已经处理的分支就提前跳过。
- **少做重复群运算**：每层接着已比较的位置继续；叶子直接利用 DFS 留下的群操作求稳定子，不再重新扫描全群、生成随后被丢弃的轨道集合。
- **降低执行和存储成本**：标签整数化，DFS 热循环移入 C++，按任务批量传结果；完整键用压缩数组 Trie，减少小对象和重复索引。
- **前缀缓存单独评价**：截断任务可以复用已经完成的子树；现有真实算例的命中收益有限，不能将整体加速归给它。

上述步骤共同作用，本轮旧版/新版对照给出组合效果，不据此分摊每一项百分比贡献。时间截止的返回集合可能随速度变化；数量上限下另核对结果一致性。新增大标签池只参与离散枚举，未新增经过几何审计、吸附或 DFT 验证的模型。

可向导师这样汇报：

> 我们保留了子群组织和深度优先搜索，主要减少三类开销：不同任务之间重复搜过的区域，搜索过程中反复做的群比较，以及叶节点和结果存储的重复处理。同时把搜索热循环放到 C++，用紧凑 Trie 保存结果。同一批输入重测，fjh 1/3 从旧版的 2.51 秒降到 0.106 秒，完整结果一致；与 CASM 在相同群、相同输出条件下比较，最大 fjh 算例是 2.77 秒对 20.94 秒，约快 7.56 倍。vba 在相同输出数量下快约 8.8–12 倍。小算例仍受准备成本影响，前缀缓存本轮没有命中，所以这部分还不能算作已验证的速度贡献。
