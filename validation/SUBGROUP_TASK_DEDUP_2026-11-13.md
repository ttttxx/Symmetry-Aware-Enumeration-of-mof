# 子群固定点任务交集的前缀排除原型

## 实现核对

- 当前 `enumerator.py` 的 DFS 不查询 Trie。`active_perm_indices` 跟踪尚不能排除的群操作，通过原指派与群像的共同已赋值前缀作字典序比较；发现群像较小即拒绝分支。它是基于群作用的规范性前缀剪枝。
- `_trie_lookup` 由 `_try_add_result` 在叶节点 canonical 生成后调用，执行完整键成员查询；Trie 现有节点未记录“某前缀的所有合法补全已处理完”的证明。
- Trie 可以用于搜索剪枝，但“前缀存在”不能直接作为剪枝条件：存有 AAB 时，AA 前缀下仍可能有未访问的 AAA。需要记录与任务约束相容的子树耗尽状态或其他覆盖证书，才能剪掉整支；跨任务还必须核对顶点轨道划分和允许标签域。
- `_compute_stabilizer_and_orbit` 同时计算稳定子大小和实际轨道列表，即全部不同群像。普通枚举器与 `RhoQuotaMOFEnumerator` 都写成 `stabilizer_size, _ = ...`，不使用轨道列表；当前 orbit_size 由 |G|/|Stab| 得到，无需物化轨道。
- Git 中最早引入该函数的 a9a243d 版本也丢弃列表，未找到必须保留这一计算的历史调用依据。可以说明代码当前无用途，不能断言作者当初的设计动机。上一轮审计报告“唯一调用方”表述过窄，配额子类也是调用方，但同样丢弃列表。

## 任务区域如何拆分

任务 H 的顶点轨道划分描述若干等式：同一个 H-轨道中的顶点必须同色。此前完整搜索的任务集合记为 C，当前任务只需搜索

`Fix(H_current) \ union(Fix(H_previous), previous in C)`。

这里实际保留全群 canonical 前缀剪枝，所以“此前完整搜索”意为该固定点域中所有 canonical 代表都已处理；省去的非 canonical 补全不会影响覆盖。

例如，已完成任务要求 c0=c1，其他顶点任意。后续任务在决定 c0、c1 后：

- c0=c1：剩余所有补全都在已完成域内，整支排除。
- c0≠c1：该已完成域不再可能包含此分支，后续不必继续检查它。

不同子群没有包含关系时也可以检查这些等式，因此能处理非嵌套的交集。并不要求显式枚举每个重复的完整构型。

“避免重复”仍有两层边界：部分交集直到最后变量赋值后才可判定，因此仍可能重复形成某些完整赋值；原型保证在本轮穷尽测试中不把这些重复赋值送入叶节点 canonical、Trie 和稳定子计算。共享的部分搜索路径和额外约束检查并不会全部消失。

## 独立实现

- `enumerator_task_dedup.py`：`TaskDedupMOFEnumerator` 继承普通枚举器，保留任务顺序、原有 canonical 前缀剪枝、叶节点处理和排序。
- 将先前 partition 的等式编译到当前任务的轨道变量；单选标签作为常量提前代入。按变量赋值深度安排等式检查，并用整数 bit mask 同时维护多个尚可能覆盖当前分支的已完成区域。
- 某区域的任一等式被违反，移除其 bit；全部等式已决定且仍成立，剪掉该分支。
- 仅完整结束的普通任务贡献覆盖区域；达到总输出上限、恒等任务新增配额或 deadline 的任务均保守地不登记。即使恰好最后一个结果碰到上限，也不声称已耗尽。
- 截断任务中已找到的个别重复结果仍由原 Trie 兜底。因此受限模式下不承诺 duplicate_leaves=0。
- 不接入 `RhoQuotaMOFEnumerator`：它只接受某个精确稳定子阶数，完成一次任务不等于已经处理该任务整个 Fix(H)。配额耗尽和精确层筛选必须纳入新的覆盖证明。
- 未修改生产 `enumerator.py`、`main.py`、论文或正式 benchmark CSV；尚未处理子群格构建成本或移除完整轨道集合，本轮隔离验证任务交集排除。

原型消除了本轮测试中所有重复叶处理，但 fjh 2/1 回退约 14%，说明等式检查的额外 Python 调度成本需要优化。下一步应将已经脱离全部覆盖区域的子树切回无需排除检查的 DFS，或融合两种检查以避免逐层包装开销；在明确消除回退后再考虑接入生产。大算例仍需减少叶节点全群规范化、轨道集合分配及 Trie 成本。
