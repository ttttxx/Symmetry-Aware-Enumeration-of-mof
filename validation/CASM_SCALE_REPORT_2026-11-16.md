# CASM 对照扩展梯度：2026-11-16

## 结果与适用范围

本轮使用已经实现的 Python 子群调度 + C++ DFS + 完整字节键去重后端，保留子群优先策略。对照扩展到 **15 个梯度、3 个拓扑**，每侧独立进程重复三次，共 **180 次运行，全部穷尽**，未触发时间或内存截断。

主要同群/同输出工作量比较中，本文在 12/15 例快于所测 CASM 接口；小 `ffc` 两例和小 `fjh` 一例仍较慢。与 CASM 同群只计数比较，本文在 11/15 例更快。最大原始空间为 16,777,216（原表最大例 531,441 的约 31.6 倍）；最大输出数为 1,328,832 个轨道。

**中大空间通常能体现当前实现的速度优势，但组合增加并不保证加速比单调增加。** `ffc` 中加速比从 5/5 的 5.36 倍降到 5/8 的 4.13 倍，随后约为 4.30、4.44 倍；`lil` 中 3/3、3/4、4/3 的原始空间逐步增加，加速比约为 3.58、3.16、2.79 倍。

论文、正式旧 CASM CSV 和默认生产后端均未更改。本轮结果采用新的同群/输出口径，不能直接塞入旧表 2 的 F 群计数与时间列。

## 规模效应的证据

- `ffc` 对角梯度从 128、2,187 增到 16,384、78,125 个组合时，主要加速比约为 0.07、0.61、2.85、5.36。首次子群构建/调度的固定成本在小空间中较突出，规模增大后相对占比下降。
- 保持 `ffc` 的 C3=5，将 C4 从 5 增至 8/12/15，加速比约为 5.36→4.13→4.30→4.44，未持续提高。原生核时间约从 0.0021 增至 0.0700 s，最大例端到端却为 0.604 s，核心之外的输出/封送/调度余项值得继续细分。
- `fjh` 从 C3=1,C4=3 的 531,441 个组合增加到 C4=4 的 16,777,216 个组合，主要加速比为 5.62→5.82，表现接近平台。最大例本文 3.600 s，CASM 同结果 20.939 s、同群只计数 17.219 s。
- 相同 531,441 个原始组合，`fjh` 的 Γ 阶为 16、轨道数 36,369，`lil` 的 Γ 阶为 4、轨道数 133,407；对应主要加速比为 5.62 和 3.58。群作用、轨道压缩程度及输出数量会改变成本，原始组合数不是唯一解释变量。
- `lil` 的轨道输出从 133,407 增到 1,328,832 时，主要加速比从 3.58 降至 2.79。该趋势与大量结果保存/物化的额外成本一致；本轮未把核心之外余项全部分解为单一原因，不将其直接归因于某个容器。

固定群中每个轨道大小不超过 |Γ|，因此仅从轨道压缩也不能推导“规模越大，速度优势无限增加”。后续期望应是固定成本摊薄后，剪枝收益与输出/内存成本共同决定平台或回落，而非预设单调改善。

## 作用群与完整性核对

1. 每个算例、每次运行都重新验证 CIF 与图的位点顺序/坐标对应。
2. 枚举 CASM 的 proper 操作，将其实际位点逆置换与本文 Γ 逐项核对，集合和阶数均相同：`ffc` 为 8、`fjh` 为 16、`lil` 为 4。
3. 用群操作的顶点循环分解独立计算 Burnside 轨道数，全部侧的计数均与相应群的独立结果一致。没有使用旧 harness 从本文计数代数反推出 CASM proper 计数的做法。
4. 两个保存结果版本的轨道大小整数和均等于 |X|，稳定子分布相同。
5. CASM 使用最大 canonical 约定，本文使用最小约定。计时结束后，双方记录都按 Γ 归一到同一个最小代表，连同完整稳定子/轨道大小排序并检查唯一性，计算 SHA-256。全部保存结果版本与重复运行的归一记录摘要一致。原始 canonical 字符串、顺序及 ID 不要求跨这两种约定逐字相同。
6. 本文侧强制 `backend="cpp"` 并断言实际后端；未发生静默 Python 回退。

## 四种测量口径

| 侧 | 群 | 计时内工作 |
|---|---|---|
| 本文混合后端 | Γ | 子群任务构建、覆盖约束编译、C++ DFS/字节去重、输出记录、标签解码、排序及覆盖检查 |
| CASM 保存同结果 | 同一 Γ | 完整占位候选生成、canonical 筛选、通过 make_invariant_subgroup 计算稳定子、原标签记录/轨道大小、排序和 ID |
| CASM 只计数 | 同一 Γ | 相同候选生成/canonical 筛选，仅累计轨道数 |
| CASM 原生完整群 | F | 原 ConfigEnumAllOccupations.by_supercell_list 只计数；保留默认 primitive/canonical 检查 |

图/群分析、依赖导入和输入准备都在计时外；本文的子群任务构建保持在计时内，未靠移动计时边界制造加速。归一摘要和独立验证在双方计时外。CASM 同群路径通过公开低层计数器与 canonical 接口逐候选传入 proper 操作列表，这部分绑定成本包含在测量中；原生 F 参考另列，便于审查接口/群选择的影响。

原生 F 与 Γ 的计数可能不同。例如最大 `fjh` 例为 Γ=1,078,816、F=577,456；F 只计数耗时约 12.935 s。这项时间与本文工作量/群均不同，不用于主要加速比。完整 F 时间和计数保存在分析 CSV/JSON 中。

## 输入梯度与资源边界

- 新增 `ffc` 的 4/4、5/5、5/8、5/12、5/15，`fjh` 的 1/4，以及 `lil` 的 2/2、3/3、3/4、4/3。原表的五个标签池基数均保留，但本轮两侧按统一排序的模板名池选择标签。
- 标签取 `nodes/3c_*.cif`、`nodes/4c_*.cif` 文件名的排序前缀；完整池清单保存在每次运行和输入清单中。这一轮没有构建这些新增组合的 CIF，也没有据此扩大已审计模型样本。
- 预检 `lil` 4/4 会输出 4,197,376 个轨道，`fjh` 3/1 至少约 2,690,421 个轨道，本轮按桌面内存边界未纳入完整结果比较；没有把未运行项称作超时或不可解。
- 既有记录中的 `vba` 晶体群/本文群作用差异需要单独处理，本轮选择已逐项通过群作用核对的 `lil` 扩展拓扑梯度。
- 每进程 watchdog 为 180 s 总时长、1536 MiB 采样 RSS，包含计时外准备和验证。全部 180 次均成功完成，边界未触发。

## 内存与主要剩余成本

RSS 为独立进程在计时结束处读取的峰值，包含共同依赖基线；不把它称作索引独占内存。

| 算例 | 本文峰值 RSS / MiB | CASM 同结果 / MiB |
|---|---:|---:|
| ffc 5/15，381,375 轨道 | 423.0 | 269.7 |
| fjh 1/4，1,078,816 轨道 | 1,087.0 | 719.0 |
| lil 4/3，1,328,832 轨道 | 896.7 | 700.5 |

当前实现以较高峰值内存换取更低耗时。它在原生核心和 Python 端同时维护所需状态，并保存 Python 结果字典/列表；CASM 参考只保存其输出列表。

最大 `fjh` 的 C++ 核心调用中位数约 1.127 s，端到端 3.600 s；`lil` 最大例核心约 0.363 s，端到端 2.562 s。差值包含子群准备、覆盖编译、参数封送、Python 结果物化/解码和排序，不能把它全部称为 DFS 时间。下一阶段应进一步拆分这些余项，特别是百万结果时的物化和重复索引状态。
