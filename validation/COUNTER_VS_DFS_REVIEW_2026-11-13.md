# 去掉 DFS 是否提效：四路同群对照

## 结论

当前 Python 实现中，取消 DFS 不保证加速。保留子群调度时，完整候选计数器在五例均慢于优化后的 DFS；去掉子群调度后，计数器只在 ffc 2/2 和 fjh 1/2 更快，另外三例仍是 DFS 更快。ffc 2/2 的差值只有约 16 微秒，不能视为稳定工程收益。

这个结论不等于 C++ 计数器也会慢。CASM 的计数与群像比较在 C++ 中执行；本实验使用 C 实现的 itertools.product 生成候选，规范性检查仍是 Python 循环。删除 DFS 不会自动获得 CASM 的底层执行速度。

## 四个版本

独立模块 `enumerator_counter.py`，生产模块不变。

| 版本 | 子群任务 | 遍历方式 | 叶节点结果 |
|---|---|---|---|
| subgroup_dfs | 原普通子群顺序，已完成域交集排除 | 上一轮整数 DFS、canonical 前缀剪枝 | Trie、完整元数据 |
| subgroup_counter | 相同任务顺序，完整候选上检查已完成域排除 | itertools.product 完整候选 + 短路 canonical | 相同 |
| single_dfs | 仅恒等任务，无子群格构建 | 同一优化 DFS | 相同 |
| single_counter | 仅恒等任务，无子群格构建 | 完整空间计数器 + 短路 canonical | 相同 |

所有版本使用相同实际位点置换群、整数标签编码、输出标签解码、Trie 存储、稳定子/轨道大小记录、排序及覆盖检查。关闭总输出上限、恒等新增配额和任务超时。单任务版本不保留原子群优先输出顺序，因此受限输出不能直接替换；穷尽代表集合相同。

计数器进一步预处理每个群操作的比较位置：跳过任务强制同色的位点对及两个固定单选域保证同色的位点对，保持其余位置在原顶点序列中的顺序；直接比较轨道赋值视图，仅接受 canonical 时展开完整 coloring。候选级 canonical 判断与稳定子计数合并，首个较小群像即拒绝候选，无需物化全部群像。

这包含针对计数器路径的预处理，不是只删除一行递归的纯单因素修改。实验用于比较可实际采用的两条路径。

## 判断边界与下一步

- DFS 能在部分赋值上拒绝所有补全均非 canonical 的分支；计数器节省递归/active 列表管理，但更多完整候选进入规范性比较。两种成本在不同空间中大小不同，不能仅由“递归有开销”决定。
- fjh 2/1 的单任务计数器约比单任务 DFS 慢 2.3 倍，最大例慢约 16%；fjh 1/2 的单任务计数器约快 28%。这不支持全局删除 DFS。
- 去掉子群调度是另一个独立选择。它减少准备和重叠任务成本，但失去高对称优先的受限输出语义；最终完整输出再按稳定子排序无法恢复此前被上限截去的代表。
- vba 的完整空间为 2^32 或 3^32。计数器仍逐个访问其候选；本轮未跑这些大空间，也未从五例推导其耗时。
- 先保留优化 DFS；穷尽路径可使用单任务入口。继续定位 Trie/结果存储成本，若进入 C++/编译核心，再在同语言/同输出工作下重新比较计数器与前缀剪枝。若需要只去掉 Python 递归，可用显式栈维持 DFS 及剪枝；这与完整候选计数器是不同改动，本轮未实现。

本轮未接入主流程，未修改论文或正式结果 CSV。
